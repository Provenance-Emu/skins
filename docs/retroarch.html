Convert a Skin to a RetroArch Overlay

Turns a .deltaskin or .manicskin into a RetroArch overlay: a .cfg file and PNG images, zipped. Everything runs in this page. Nothing is uploaded.

1 — Pick a skin

Drop a skin file here, or open this page from a skin's "Convert to RetroArch" button and it loads from the catalog.

Install on RetroArch for iOS

    
RetroArch has no "open overlay" hand-off: a file shared to it lands in its downloads folder as content. So the overlay goes in through the Files app. Three steps.

    
    
      
  1. Download the zip. On iPhone, Safari puts it in Files › Downloads. Tap it there and Files unzips it into a folder named after the skin, with a .cfg, PNGs and a README inside.
    2. 
      
  2. Long-press that folder › Move › On My iPhone › RetroArch › RetroArch › overlays › Move. (Open RetroArch once first so the folder exists. The share sheet's Save to Files into that folder works too; the zip unzips in place when tapped.)
    3. 
      
  3. In RetroArch: Settings › On-Screen Display › On-Screen Overlay › Overlay Preset, pick <skin>/<skin>.cfg. To keep it for one game, Quick Menu › Overrides › Save Game Overrides.
    4. 
    

    
Auto-Rotate Overlay is on by default on iOS and switches between the landscape and portrait layouts in the file. Auto-Scale Overlay keeps the layout's proportions on a screen of a different shape. Set Overlay Opacity to 1.0 if the artwork looks faded (RetroArch's default is 0.7).

    
For people who edit retroarch.cfg directly:

    
input_overlay_enable = "true"
input_overlay = "~/Documents/RetroArch/overlays/<skin>/<skin>.cfg"
input_overlay_opacity = "1.000000"
input_overlay_hide_in_menu = "true"

    
Linux, Windows, macOS and Android RetroArch read the same files; put the folder in the overlays directory shown under Settings › Directory.

  


  
  

    
What converts and what doesn't

    
    
      
  • Buttons keep their hitbox: the skin's frame plus its extended edges, as a rect descriptor. Combo buttons become a|b. menu opens RetroArch's menu; fast-forward and quick save / load buttons become toggle_fast_forward, save_state and load_state.
    • 
      
  • A four-way pad becomes nine rect descriptors on a 3×3 grid of its hitbox: four directions, four diagonals (up|left), empty centre. That is how Delta reads a d-pad and how RetroArch's stock overlays draw one. Pads made of other buttons (N64 C buttons) get the same grid with those binds.
    • 
      
  • Thumbsticks become analog_left / analog_right with the skin's stick image as a movable cap.
    • 
      
  • Face buttons follow each libretro core's default RetroPad layout, so Genesis A B C land on Y B A, N64 Z on L2, PlayStation shapes on their usual RetroPad buttons.
    • 
      
  • Both orientations go in one .cfg as separate overlays (landscape first), and a skin's alternate layouts (altRepresentations) become a second pair that its toggle button switches to. A portrait layout that only covers the bottom of the screen is placed there with overlayN_rect. The game screen area is made transparent, since RetroArch draws the overlay on top of the video; RetroArch places the video itself (Settings › Video › Scaling).
    • 
      
  • Not converted, and listed in the result when a skin has them: DS touch-screen inputs (RetroArch cores take touch straight from the screen), per-game layouts, screen filters, inputs with no RetroArch bind, and layouts whose artwork is missing from the archive. Apple TV layouts convert as artwork only. Screen positions are informational; RetroArch places the video itself.
    • 
    

    
Prior art: warmenhoven/skin2overlay did this first for Delta skins. This page is EmuSkins' own implementation, written against RetroArch's overlay loader (tasks/task_overlay.c). It uses pdf.js to render PDF artwork and JSZip to read and write the archives. Source: retroarch-convert.js; the button table is retroarch-input-map.json, shared with SkinKit.
