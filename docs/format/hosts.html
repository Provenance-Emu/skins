Hosting a skin with panels

For emulator developers: what your app passes to a skin that has panels, and what the skin tells you back.

A format 2.0 skin can hold panels: a memory unit with a live screen, a row of arcade buttons. The app says what it can supply, the skin shows what it can use, and the app learns what the skin is showing so it can hide its own copy. This page is the Swift side, in SkinKit's SkinKitUI. The format side is in the reference under Capabilities and Panels, and the examples have one to try.

The whole thing in one view

@StateObject private var pictures = Skin2PictureStore()
@State private var skinShowsVMU = false

DeltaSkinView(skin: skin, traits: traits, isInEmulator: true, inputHandler: handler,
              capabilities: ["picture.vmu.p1"],
              pictures: pictures,
              onProvidedChange: { provided in skinShowsVMU = provided.pictures.contains("vmu.p1") })

if !skinShowsVMU { FloatingVMU() }   // the app's own copy, as before

The three parameters have defaults, so existing call sites compile unchanged. A classic skin, or a 2.0 skin drawn as its classic bake, never reports anything, and the app's own controls stay.

Say what you can supply: capabilities

capabilities is a set of names from SkinKit's closed list (Skin2Capabilities): picture.vmu.p1 to picture.vmu.p4, and input.<name> for each semantic input. Pass what is true right now for the running core and game, and change it when that changes: a memory unit is unplugged, a game has no coin slot. A panel whose needs are not all there is absent, and the skin lays out again without it. A control the player was holding in it is released first.

Pass a capability whether or not the player has your own copy switched on. The capability says the app can supply the picture, not that the player wants your floating window.

Hand over pictures: Skin2PictureStore

pictures.set(cgImage, for: "vmu.p1")   // a finished image, any resolution
pictures.set(nil, for: "vmu.p1")       // no picture now

The app owns the store and copies each picture into it; SkinKit never reads from a core. Set an image when the picture changes and nil when there is none, including before the game has drawn anything. An all-blank buffer is not a picture. The skin draws each picture in a layer of its own, so a new one does not redraw the skin, and anything the skin lists after the screen (glass, a glare) stays on top. How the picture looks is yours: apply your LCD filter before you hand it over.

Learn what the skin shows: onProvidedChange

It is called when the view appears and whenever the answer changes, with a Skin2Provided:

  • pictures: the sources the skin is showing and you have delivered a picture for.
  • inputs: the semantic inputs the skin has a control for.
  • panels: each present panel's name and whether it is open.

The rule for each of your own copies is one line: show my floating memory unit unless provided.pictures contains vmu.p1. A shelf the player closed still counts, because they closed it on purpose and its handle is there to open it. When the view goes away the callback gets an empty value, so your copy comes back.

Take inputs that are not pad buttons: DeltaSkinSemanticInputHandling

extension MyInputHandler: DeltaSkinSemanticInputHandling {
    func semanticInput(_ name: String, pressed: Bool) {
        if name == "arcade.coin1" { core.setCoin(1, down: pressed) }
    }
}

Dotted names such as arcade.coin1 arrive here and never at buttonPressed. The skin shows such a control only while you list input.arcade.coin1 in capabilities, so you decide per core and per game which ones exist.

Shelves are the skin's business

The skin view owns which shelves are open. A shelf's handle toggles it and is never sent to your input handler. The view remembers the player's choice per skin, and animates the change unless Reduce Motion is on. Do not pass flags that start with panel.; the view ignores them.

Draw one part alone: Skin2PartView

Skin2PartView(part: "std.vmu", capabilities: ["picture.vmu.p1"], pictures: pictures)
    .frame(width: 150, height: 112)

It draws one part from the standard library filling the view, exactly as it looks inside a skin. Use it for your own floating accessory in place of hand-written drawing, so the unit looks the same in and out of a skin.

Older readers and classic apps

A skin that uses std.vmu lists parts.std@2.1 in requires. An app built before that part draws the skin's classic bake, which holds the controller without the panel, and keeps its own memory unit on screen. Delta and Manic read the same bake.
