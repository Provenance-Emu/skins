Skin format 2.0

A 2.0 skin is one skin.json that describes a controller as a tree of screens, controls and artwork. A compatible app lays the tree out for the display and orientation in front of it. The same archive ships a classic layout and artwork for apps that only read info.json.

What a source looks like

This is the controller the tutorial builds: a 4:3 screen, two groups anchored to the bottom corners, and standard parts for the sticks and buttons. Switch the orientation to see the same source resolve for landscape.

What readers need

List every feature the source uses in requires, including features used inside expanded parts and variants. For example, a standard stick needs parts.std@2.0 and controls.thumbstick. The validator reports omitted capabilities, and the playground can write the list for you. A reader uses the responsive source when it supports the format version and every required capability.

What the classic bake carries

The classic info.json has complete representations with artwork, screen frames and control hit areas. Bake both standard and edge-to-edge iPhone layouts in portrait and landscape. The baker includes skin.json and a format2 marker in the archive, so classic readers can keep using info.json.

Artwork-only themes remain classic asset overrides. Themes that move controls or screens get separate archives. A game match bakes to gameOverrides, a toggle variant to altRepresentations, and a selectable variant to its own archive.

After the source validates

  1. Bake it into a .deltaskin with skinkit-bake. Step 6 of the tutorial has the command.
  2. Import the archive in the app and check both orientations.
  3. Submit it to the catalog so it shows up in the in-app browser.

To move or resize the parts of a classic skin that already exists, use the skin editor.

The full format design lives in SkinKit. Emulator developers replacing a controller that code generates can follow the conversion notes.
