Here's the plan for big sets like yours. Short version: you don't need to trim anything or keep a second repo.

**What's changing**

Your arcade set is really one design with options: device, look, controls, stick, hand and colour. Right now the site shows it as 150 cards (one per layout, 22 colours each). I'm adding a level above that, so the whole set becomes **one card**. Opening it gives a picker for each option instead of a wall of names:

- Device (Dynamic Island / Notch / iPad), chosen for you in the apps
- Hand (right / left), from a setting in the apps
- Game (horizontal / Tate), Controls (1 to 6 buttons, twin stick…), Stick (joystick / D-pad), Look (normal / full screen)
- Colour, as swatches

Combinations that don't exist are greyed out, and whatever the picker shows is the file that installs. The site's totals will count designs first and files second, so one large set no longer reads as 70% of the catalog. Every existing skin link keeps working.

Design doc: `specs/2026-11-23-skin-lines-design.md` on the `design/skin-families` branch.

Nothing. Your names are regular enough that I can describe the set from them on my side (all 150 layouts × 22 colours parse cleanly). Please keep the naming you have: "Dynamic Island", "iPad", "Tate", "Full Screen", "Left-Handed", "D-Pad", "N-Button", "Twin Stick", and the colour after the " - ".

Optional, later: if you'd like to control the set's name, the default layout and colour, or the order of the colours yourself, you'll be able to add a small `.emuskins.yml` file to your repo. I'll document it when it's ready.
